# Built-in Shader Analysis Report

This report covers the built-in shaders of Cute Framework: how they work, bugs found during
review, and performance optimization opportunities. File/line references are against the
current state of this branch.

---

## 1. Architecture Overview

### Where the shaders live

| File | Role |
|---|---|
| `tools/builtin_shaders.h` | **Source of truth.** GLSL 450 source for all built-in shaders and include modules. |
| `src/data/builtin_shaders_bytecode.h` | Generated cache: SPIR-V blobs, transpiled GLSL ES 3.00 source, and reflection tables. Regenerated by `cute-shaderc -type=builtin` (CMake rule at `CMakeLists.txt:514-523`, dependent on `tools/builtin_shaders.h`). |
| `tools/cute_shader.cpp` | The compiler: glslang (GLSL 450, Vulkan 1.3 semantics) → SPIR-V 1.3, then SPIRV-Cross → GLSL ES 3.00, plus SPIRV-Reflect for uniform/input reflection. |
| `src/cute_graphics.cpp` | Loads built-ins at startup (`cf_load_internal_shaders`, lines 212-224): compiles from source when `CF_RUNTIME_SHADER_COMPILATION=ON`, otherwise uses the embedded bytecode. |

The SDL_GPU backend consumes SPIR-V; the GLES 3.0 backend consumes the transpiled
GLSL ES 3.00 source. On Emscripten the SPIR-V blobs are compiled out of the bytecode
header entirely (`#ifndef __EMSCRIPTEN__`) to save binary size.

### Shader inventory

- **`s_draw` (vs/fs)** — the primary "uber shader" behind all of `cute_draw.h`.
- **`s_blit` (vs/fs)** — composites one canvas onto another (`cf_draw_canvas`).
- **`s_basic` (vs/fs)** — renders white; testing only. *Currently unreferenced at runtime.*
- **`s_backbuffer` (vs/fs)** — was for canvas→swapchain copy. *Currently unreferenced at runtime* — both backends use native blits instead (`cf_gles_blit_canvas` uses `glBlitFramebuffer`, SDL_GPU uses `SDL_BlitGPUTexture`).
- **Include modules** injected via a virtual `#include` system: `gamma.shd`, `blend.shd`, `distance.shd`, `smooth_uv.shd`, and `shader_stub.shd`.

### User shader injection

`shader_stub.shd` is the extension point. The default stub is an identity `shader()`
function; `cf_make_draw_shader*` re-compiles `s_draw_fs` (and a twin `s_blit_fs`) with the
user's source substituted for the stub (`cf_make_shader_from_source_internal`,
`src/cute_graphics.cpp:177-195`). Every user draw shader automatically gets a paired blit
shader, tracked in `draw_shd_to_blit_shd` so `cf_draw_canvas` can run the same effect during
canvas composition.

### How the draw shader works

**Vertex shader** (`s_draw_vs`): pure passthrough. The CPU pre-transforms positions by the
MVP (`posH`), so the VS just forwards 11 attributes. The only computation is
`v_shape.y = in_shape.y * 0.5` — stroke width is halved because `sdf_stroke` expands
`abs(d) - v_stroke` on both sides of the isosurface.

**Fragment shader** (`s_draw_fs`): a branch-per-primitive uber shader. Each primitive tags
its 6 vertices (two triangles, no index buffer) with a float `type`:

| type | primitive | path |
|---|---|---|
| 0 | sprite | atlas sample |
| 1 | text | `v_col * tex.a` (per-corner vertex colors) |
| 2 | box | SDF `distance_box` |
| 3 | segment/capsule/circle | SDF: min of two `distance_segment`s (circle = degenerate capsule) |
| 4 | triangle | flat/per-vertex color |
| 5 | triangle SDF | `distance_triangle` |
| 6 | polygon (≤8 verts) | `distance_polygon` |

SDF primitives then run `sdf()` (in `distance.shd`), which applies fill vs. stroke selection
and screen-space anti-aliasing (`v_aa` is a pixel-scaled AA width maintained by
`CF_Draw::set_aaf`, camera-zoom aware). Finally: alpha modulation, the user `shader()` hook
with a `ShaderParams` struct (view pos, uv, uv bounds, screen uv, 4 user attributes), and an
optional zero-alpha `discard`.

**Filter modes** (`CF_DrawFilterMode`) combine a hardware sampler with a shader path:
- `NEAREST` → nearest sampler, plain UV.
- `LINEAR` → linear sampler, plain UV.
- `SMOOTH` (default) → linear sampler **plus** the `smooth_uv()` function, which snaps UVs
  to texel seams with a `fwidth`-scaled ramp — the standard "pixel art with smooth
  subpixel motion" technique.

The `u_use_smooth_uv` uniform drives this, but note its value semantics are inverted from
its name: `0` means *apply* `smooth_uv()`, `1` means plain UV (see
`src/cute_draw.cpp:383-385`). The C++ side and shader agree, so behavior is correct, but
the naming is a maintenance trap (more below).

### How the blit shader works

`s_blit` draws a canvas as a textured quad into another canvas (used by `cf_draw_canvas`).
The CPU computes world/clip positions for the quad (`s_blit`, `src/cute_draw.cpp:3382-3494`),
the FS samples with `smooth_uv()` and runs the user `shader()` hook with the canvas'
`u_texture_size` and the command's user params as attributes.

## 2. Bugs

### Bug 1 (real, visible): `sdf()` self-mix — non-AA stroke path is dead, and `v_aa == 0` produces undefined rendering

`tools/builtin_shaders.h:194-208`:

```glsl
vec4 stroke_aa = mix(b, a, smoothstep(0.0, v_aa, wire_d));
vec4 stroke_no_aa = wire_d <= 0.0 ? b : a;

vec4 fill_aa = mix(b, a, smoothstep(0.0, v_aa, d));
vec4 fill_no_aa = clamp(d, -1.0, 1.0) <= 0.0 ? b : a;

vec4 stroke = mix(stroke_aa, stroke_aa, v_aa > 0.0 ? 1.0 : 0.0);   // <-- BUG
vec4 fill = mix(fill_no_aa, fill_aa, v_aa > 0.0 ? 1.0 : 0.0);
```

The stroke selection mixes `stroke_aa` with **itself** — an obvious copy/paste slip
(compare with the `fill` line below it). `stroke_no_aa` is computed and never used.

Consequences when the user disables anti-aliasing (`cf_draw_push_antialias(false)` →
`v_aa == 0`):

1. Strokes still take the "AA" path, but `smoothstep(0.0, 0.0, x)` has **undefined results**
   per the GLSL spec (requires `edge0 < edge1`). Typical hardware computes
   `clamp((x-e0)/(e1-e0), 0, 1)` = `clamp(0/0)` = NaN.
2. Worse, the NaN can poison the *fill* path too: `fill = mix(fill_no_aa, fill_aa, 0.0)`
   is evaluated as `fill_no_aa*(1-0) + fill_aa*0`, and `NaN * 0 = NaN`. So with AA disabled,
   *all* SDF shapes risk NaN output (usually renders as black or transparent, driver-dependent).

**Fix** — select with ternaries (which don't arithmetically propagate NaN from the
unselected operand) and use the intended variable:

```glsl
vec4 stroke = v_aa > 0.0 ? stroke_aa : stroke_no_aa;
vec4 fill   = v_aa > 0.0 ? fill_aa   : fill_no_aa;
```

Even better, guard the `smoothstep` calls entirely (also saves work; see Perf 3):

```glsl
vec4 sdf(vec4 a, vec4 b, float d)
{
	float wire_d = sdf_stroke(d);
	vec4 stroke, fill;
	if (v_aa > 0.0) {
		stroke = mix(b, a, smoothstep(0.0, v_aa, wire_d));
		fill   = mix(b, a, smoothstep(0.0, v_aa, d));
	} else {
		stroke = wire_d <= 0.0 ? b : a;
		fill   = d      <= 0.0 ? b : a;
	}
	result = mix(stroke, fill, v_fill);
	return result;
}
```

### Bug 2 (real, visual): blit shader ignores the filter mode

The draw FS respects `u_use_smooth_uv`, but `s_blit_fs` (`tools/builtin_shaders.h:491-538`)
applies `smooth_uv()` unconditionally:

```glsl
vec4 color = texture(u_image, smooth_uv(v_uv, u_texture_size));
```

Meanwhile the CPU dutifully sets a `u_use_smooth_uv` uniform for the blit material
(`src/cute_draw.cpp:3464-3466`) — but the blit shader's uniform block doesn't declare it,
so the value is silently dropped by the material system.

Consequence: `cf_draw_canvas` with `CF_DRAW_FILTER_LINEAR` does **not** give plain bilinear
sampling — it always gets the smooth-UV pixel-art ramp. (With `NEAREST` the math is applied
but harmless, since the nearest sampler picks the same texel.)

**Fix** — mirror the draw shader in `s_blit_fs`:

```glsl
layout (set = 3, binding = 0) uniform uniform_block {
	vec2 u_texture_size;
	int u_alpha_discard;
	int u_use_smooth_uv;
};
...
vec2 uv = u_use_smooth_uv == 0 ? smooth_uv(v_uv, u_texture_size) : v_uv;
vec4 color = texture(u_image, uv);
```

### Bug 3 (latent): `safe_norm()` isn't safe

`tools/builtin_shaders.h:152-155`:

```glsl
vec2 safe_norm(vec2 v, float l)
{
	return mix(vec2(0), v / l, l == 0.0 ? 0.0 : 1.0);
}
```

`v / l` is evaluated *before* the mix. When `l == 0`, that's `0/0 = NaN`, and
`mix(0, NaN, 0.0)` = `0*(1) + NaN*0` = **NaN** — the guard guards nothing. No built-in
code path calls it, but it ships in `distance.shd`, which is included into every user
draw shader as public helper API.

**Fix:**

```glsl
vec2 safe_norm(vec2 v, float l)
{
	return l == 0.0 ? vec2(0.0) : v / l;
}
```

### Bug 4 (code smell with teeth): `sdf()` writes the fragment output global

`sdf()` assigns `result` (the `out vec4` fragment color) *and* returns the same value.
`main()` assigns `result` again at the end, so today this is masked — but any user shader
that calls the documented SDF helpers and then relies on its own `result` handling can be
silently stomped, and it makes the helper unusable in non-fragment contexts.
**Fix:** use a local and just `return` it.

### Bug 5 (dead code masquerading as live): `u_texel_size` uniform doesn't exist

`src/cute_draw.cpp:379-380` sets a `u_texel_size` uniform every batch, but no built-in
shader declares it (the FS block has only `u_texture_size`, `u_alpha_discard`,
`u_use_smooth_uv`). The material system silently skips unmatched names, so this is a no-op
that misleads readers (and any user shader relying on it would work — but nothing
documents it). **Fix:** delete the two lines, or declare it in the uniform block if it's
meant to be user-visible API.

### Notes (not bugs, but worth knowing)

- **`u_use_smooth_uv` semantics are inverted from the name** (`0` = use smooth_uv,
  `1` = don't). C++ and GLSL agree so rendering is correct, but it *reads* like the classic
  inverted-flag bug and will trip up contributors. Renaming to `u_skip_smooth_uv`, or
  flipping the value convention on both sides, would remove the trap. Any rename must touch
  `tools/builtin_shaders.h`, `src/cute_draw.cpp` (2 sites), and regenerate the bytecode header.
- **`s =- s;`** in `distance_polygon` (`tools/builtin_shaders.h:272`) parses as `s = -s`
  and is correct, but is one keystroke away from `s -= s`. Write `s = -s;`.
- **Sprites ignore `v_col`** in the FS (`c = is_sprite ? gamma(tex_c) : c`). This is
  consistent — the CPU always sends premultiplied white for sprites — but it means the
  color attribute is uploaded for every sprite vertex and discarded, and if anyone ever
  wires sprite tinting through `geom.color` it will silently not render. Worth a comment
  in the shader.
- **Type dispatch relies on exact float equality ranges** (`v_type > 0.5 && v_type < 1.5`
  etc.). Safe today because all 6 vertices of a primitive carry the same integer-valued
  float (interpolation of equal values is exact), but a `flat` int would be more robust
  and free.

## 3. Performance

### GPU-side

**Perf 1: every fragment pays for a texture fetch + 2× `pow()` — including pure SDF shapes.**
`s_draw_fs` unconditionally executes:

```glsl
vec4 tex_c = de_gamma(texture(u_image, uv));    // pow(rgb, 2.2)
c = is_sprite ? gamma(tex_c) : c;               // pow(rgb, 1/2.2)
```

For boxes/segments/triangles/polygons the fetch and both `pow` vec3s are thrown away.
Since `v_type` is uniform across each primitive, a real branch is coherent (no divergence
within a wave for same-type batches, which is the common case):

```glsl
vec4 c = vec4(0);
if (is_sprite || is_text) {
	vec2 uv = u_use_smooth_uv == 0 ? smooth_uv(v_uv, u_texture_size) : v_uv;
	vec4 tex_c = texture(u_image, uv);
	c = is_sprite ? tex_c : v_col * tex_c.a;
} else if (is_tri) {
	c = v_col;
}
```

**Perf 2: the gamma round-trip is an identity function.**
`gamma(de_gamma(x))` = `pow(pow(|x|, 2.2), 1/2.2)` = `|x|` — the sprite path burns six
scalar `pow`s per fragment to reproduce the input (with added precision loss), and the text
path only reads `tex_c.a`, which `de_gamma` doesn't touch. Unless a linear-space blend step
is planned between the two calls, both can simply be removed (as in the Perf 1 snippet).
Keep `gamma.shd` itself — it's public API for user shaders.

**Perf 3: `sdf()` always computes both the AA and non-AA variants of both fill and stroke.**
Four color candidates + two `smoothstep`s per fragment, then two mixes to discard half of
the work. The restructured `sdf()` in Bug 1's fix computes exactly one fill and one stroke.
If `v_fill` is also effectively boolean (it is: the CPU sends 0.0/1.0), a further branch on
it skips the stroke math for filled shapes entirely.

**Perf 4: dead code survives into the GLES backend verbatim.**
SPIRV-Cross keeps the unused `stroke_no_aa` computation (see
`src/data/builtin_shaders_bytecode.h:2252-2258`) — glslang is run with the optimizer in
default mode and no SPIR-V opt pass strips it. Fixing Bug 1 removes it naturally, but for
general hygiene consider running `spirv-opt` (or glslang's `optimizeSize`) over built-ins
in `cute-shaderc`; mobile/web GPUs get whatever text lands in the file.

**Perf 5: vertex bandwidth is heavy — 912 bytes per quad.**
`CF_Vertex` is 152 bytes (8 `vec2` shape slots, color, 4 shape params, blend/posH, user
attributes, uv bounds), and every quad is 6 unindexed vertices. Options, in increasing
order of invasiveness:

1. **Index buffer**: 4 vertices + 6 indices per quad ⇒ ~33% bandwidth cut, near-zero risk.
2. **Compress attributes**: `posH`/`uv`/`uv_bounds` as 16-bit (half or unorm), `type`/`n`
   as bytes; `aa`/`stroke`/`radius` rarely need full 32-bit. A ~60-80 byte vertex is realistic.
3. **Split the uber-vertex**: sprites/text (the high-count primitives) need ~40 of those
   152 bytes; the 8-slot polygon payload exists on every glyph. Two pipelines (sprite-like,
   SDF-like) or per-instance attributes would cut sprite bandwidth ~3×, at the cost of
   batching complexity — this is the big architectural lever, only worth it if profiling
   shows vertex fetch bound scenes (lots of text is the likely trigger).

**Perf 6: polygon SDF copies 8 points into a global array per fragment** and loops with a
dynamic bound. Fine for `N ≤ 8`, but the copy into `pts[]` happens even before the branch
confirms the primitive is a polygon on some compilers; keeping the copy inside the
`is_poly` branch (it already is) and passing `v_ab..v_gh` directly would avoid the global
array on backends that don't promote it to registers.

### CPU-side

**Perf 7: remove the dead `u_texel_size` set** (Bug 5) — one interned-pointer map miss per
batch, trivial but free.

**Perf 8: `u_use_smooth_uv` is set on the blit material that can't consume it**
(Bug 2's CPU half) — fixing the blit shader makes this useful instead of dead.

**Perf 9: dead embedded shaders.** `s_basic` and `s_backbuffer` are compiled, embedded
(SPIR-V + GLSL ES source + reflection tables — several KB), and never referenced by any
runtime code path. Either drop them from `s_builtin_shader_sources` in
`tools/builtin_shaders.h` (and regenerate) or leave a comment explaining they're kept for
debugging; today they read as load-bearing.

*(Non-issue verified: material uniform lookup uses interned-pointer comparison, not
`strcmp`, so per-draw uniform matching is already cheap.)*

## 4. Suggested fix priority

| # | Item | Risk | Payoff |
|---|---|---|---|
| 1 | Bug 1 `sdf()` self-mix / `v_aa==0` NaN | none (restores intent) | correctness on AA-off, removes dead math |
| 2 | Bug 2 blit `u_use_smooth_uv` | low | `LINEAR` canvas blits behave as documented |
| 3 | Bug 3 `safe_norm` NaN | none | user-shader helper actually safe |
| 4 | Perf 1+2 branch texture/gamma path | low (visual output identical: gamma round-trip is identity) | biggest built-in FS win, helps SDF-heavy and sprite-heavy scenes |
| 5 | Bug 5 / Perf 7 `u_texel_size` | none | dead code removal |
| 6 | Bug 4 `sdf()` writing `result` | none | API hygiene |
| 7 | Perf 5 (indexing → compression → split) | medium→high | bandwidth; profile first |
| 8 | Perf 9 dead built-ins | none | binary size, clarity |

**Regeneration reminder:** any edit to `tools/builtin_shaders.h` requires regenerating
`src/data/builtin_shaders_bytecode.h` (build with `CF_CUTE_SHADERC=ON`; the CMake custom
command runs `cute-shaderc -type=builtin`). The two files are currently in sync — the
Bug 1 self-mix is faithfully present in both the SPIR-V and the GLES text.
